# DOST SETUP/iFund Project Financial Monitoring Dashboard

A Streamlit dashboard for a DOST monitoring officer to check a cooperator/MSME's
financial status at a glance: variance against the approved proposal, repayment
coverage, investment appraisal, and a short evidence-based narrative.

Sample data is built from the uploaded **SJL Corporation SETUP/iFund proposal**.
Baseline/projected figures are transcribed from that proposal. Monthly actuals
and repayment records are **simulated** for demonstration — this is clearly
separated in the data files (see below).

## Installation

```bash
pip install -r requirements.txt
```

## Gemini API Configuration

The Narrative tab calls the Gemini API. Configure your key using **one** of these
(never paste it into the app or commit it to source control):

**Option A — Streamlit secrets**
```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
# then edit .streamlit/secrets.toml and paste your key
```

**Option B — Environment variable / .env file**
```bash
cp .env.example .env
# then edit .env and paste your key
```

Every other part of the dashboard (Overview, Actuals & Variance, Repayment &
Appraisal) works fully without a Gemini key. Only the Narrative tab depends on it,
and it fails gracefully (with a retry option) if the key is missing or the API
call fails.

## Run

```bash
streamlit run app.py
```

## How the four tabs work

- **Overview** — one-screen status: KPI cards, a projected-vs-actual chart, a plain
  status summary, and the most important flags only.
- **Actuals & Variance** — the five monitored line items (Gross Sales, Raw Materials,
  Direct Labor, Manufacturing Overhead, Operating Expenses), monthly and cumulative
  variance against the approved projection, and an adjustable review threshold.
  An optional, collapsed **"Simulate monthly actuals"** panel lets you edit the sample
  numbers or apply a quick scenario (on-track / raw-material spike / sales drop) to
  see how the rest of the dashboard reacts — this is for testing only.
- **Repayment & Appraisal** — contractual amortization due vs. actually paid (a
  factual coverage check, kept separate from the variance flags above), and the
  proposal's own investment appraisal figures. Actual ROI is only computed once a
  full 12 months of actuals exist for the year; IRR/NPV/BCR are always shown as the
  proposal's reference figures, never recomputed from partial monitoring data.
- **Narrative** — a four-part (Evidence → Observation → Possible Contributing
  Factors → Question for Review) summary generated by Gemini from the verified
  numbers above. Gemini only writes the language; it never calculates a figure or
  determines a status.

## Data Replacement

Everything reads from the CSVs in `data/` through plain `pandas.read_csv()` calls in
`app.py`. To connect real DOST monitoring data, replace those CSVs (or point the
loaders at a database/API) with the same column names — no dashboard code needs to
change. `data/generate_sample_data.py` documents the exact schema each file expects.

## Design notes

- Financial Variance, Repayment status, and Appraisal status are always shown
  **separately** — the app does not combine them into a single composite risk score.
- Missing data is shown as "Not Reported" / "Insufficient Data", never treated as
  zero, unpaid, or failed.
- All calculations happen in `dost_utils/calculations.py`, independent of Streamlit and
  independent of Gemini — you can unit-test it on its own.
